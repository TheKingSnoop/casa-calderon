# 0004 · Toolchain and quality gates

- **Status:** Accepted
- **Date:** 2026-11-13
- **Deciders:** Israel Calderon

## Context

Four people on different machines (Windows and possibly Mac) will work on the repo. We want consistent code, early feedback, and a `main` branch that always builds, without spending money.

## Decision

- **Node.js 26 (LTS)**, pinned in `.nvmrc` and `engines`. Managed locally with **fnm**, which works the same on Windows and Mac and auto-switches versions from `.nvmrc`. CI reads the same `.nvmrc`. `.npmrc` sets `engine-strict=true`, so `npm install`/`npm ci` **fails immediately** on the wrong Node version instead of only warning (added 2026-11-17, after an install under Node 20 silently rewrote `package-lock.json`).
- **Docker / Dev Containers: not for now.** Production is static files on S3 (no runtime container to match), and `.nvmrc` + fnm + `engine-strict` cover the only real source of drift (Node). Docker Desktop + WSL2 would add significant setup weight on Windows. Revisit as an _optional_ Dev Container if environment issues appear or the AWS tooling becomes hard to install (see Roadmap backlog).
- **Next.js 16.4** (static export), **React 19**, **Tailwind CSS 4**: as generated by `create-next-app@16.4.6`.
- **TypeScript 5** and **ESLint 9**: kept at the versions `create-next-app` ships with, even though TypeScript 7 and ESLint 10 exist, because Next.js's tooling is built and tested against these. We'll upgrade when `eslint-config-next` does.
- **Prettier** for formatting, with **eslint-config-prettier** so the two tools don't conflict.
- **Husky + lint-staged** pre-commit hook: format and lint the staged files.
- **Vitest** for unit tests.
- **Playwright** (Chromium only, added in M3) for end-to-end smoke tests against a drafts build and the real production build, served by a small CloudFront-like server with the production security headers. Firefox/WebKit can be added later.
- **`.gitattributes`** forcing LF line endings.
- **GitHub Actions CI** on every PR and push to `main`: format check, lint, type-check, test, build. It has a 15-minute timeout and cancels superseded runs to protect the free Actions minutes.

See [06 · Development Workflow](../06-development-workflow.md) for how these fit together.

## Consequences

- Problems are caught in seconds (editor/hook) rather than in review.
- Commits take a few extra seconds.
- Contributors must use Node ≥ 26. On older versions, `npm install` stops with an `EBADENGINE` error.
- `create-next-app@16.4` enables `cacheComponents`/`partialPrefetching` by default; these are **disabled** because they're incompatible with `output: "export"`.
- Known: `npm audit` reports 7 moderate issues in a dev-only dependency (`minimatch` via `typescript-eslint`, pinned by `eslint-config-next`). There are none in production dependencies, and the fix is waiting on an upstream release.
